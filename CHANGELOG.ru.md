# История изменений

🌐 [English](CHANGELOG.md) · **Русский**

Все значимые изменения в этом проекте документируются в этом файле.
Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
проект следует [семантическому версионированию](https://semver.org/lang/ru/).

## [Не выпущено]

### Добавлено
- Пример-плеер: экран **«О программе»** (`i`) — текущая версия, каталог данных, состояние журнала
  запросов и проверка обновлений по требованию (`r`). Автоматическая проверка умеет сообщать только
  плохие новости; здесь есть ответ и на вопрос «у меня уже последняя?».
- Пример-плеер: пункт **«Обновиться»** в главном меню (`u`), появляется, пока обновление доступно. Он
  запускает тот же установщик, что описан в README, — теперь на уведомление можно среагировать, а не
  искать и перенабирать команду установки. На Windows установщик стартует в отдельном окне и ждёт
  выхода плеера, потому что запущенный `ymt.exe` перезаписать нельзя; на Linux он работает прямо в
  терминале, и плеер завершается после него. В обоих случаях плеер завершается: в памяти всё ещё
  старая сборка.
- Пример-плеер: версия выводится рядом с подзаголовком в стартовом баннере.

### Изменено
- Пример-плеер: проверка обновлений выполняется при запуске и каждые 30 минут вместо «не чаще раза в
  сутки». Два запроса в час — это далеко от лимита GitHub без авторизации, зато релиз, вышедший при
  запущенном плеере, замечается без перезапуска. Файл-отметка суточной проверки больше не нужен;
  оставшийся от прошлых версий удаляется при первом запуске.
- Пример-плеер: `YM_PLAYER_NO_UPDATE_CHECK` теперь отключает только автоматическое расписание. Явная
  проверка с экрана «О программе» работает — отказ от уведомлений и просьба, чтобы кнопка ничего не
  делала, это разные вещи.
- Пример-плеер: главное меню запоминает выбранный пункт по действию, а не по индексу, поэтому
  появление пункта «Обновиться» больше не сдвигает курсор под руками у пользователя.

## [0.5.0] - 2026-08-22

### Добавлено
- **`YandexMusic.Ynison`** — новый пакет с состоянием воспроизведения в реальном времени и пультом.
  Основной пакет `YandexMusic` больше не содержит никакого websocket-клиента: он не зависит ни от
  чего, кроме BCL, а это ровно то, что нужно подавляющему большинству потребителей. Оба пакета
  выпускаются из этого репозитория на одной линии версий.

### Изменено
- **Ломающее**: `CreateYnisonClient` больше не член `IYandexMusicClient`. Это метод расширения из
  `YandexMusic.Ynison`, так что `client.CreateYnisonClient()` по-прежнему компилируется — добавьте
  пакет и `using YandexMusic.Ynison;`. Именно эта связка мешала ядру быть самодостаточным: интерфейс
  ядра называл тип из Ynison, и websocket-клиент тащил за собой каждый потребитель REST API.
- **Ломающее**: `YandexMusicYnisonException` поставляется из сборки `YandexMusic.Ynison`. Namespace
  (`YandexMusic.Exceptions`) и форма не изменились, блоки `catch` пересобираются как есть — обновить
  нужно только бинарную ссылку.

### Удалено
- `RELEASING.md` / `RELEASING.ru.md`. Это была инструкция для мейнтейнера — настройки репозитория,
  аккаунт на nuget.org, теги, — в которой не было ничего для тех, кто пользуется библиотекой или
  участвует в её разработке.

## [0.4.0] - 2026-08-22

### Добавлено
- Пример-терминал ставится одной командой и запускается как `ymt`. `scripts/install.ps1`
  (`irm … | iex`) и `scripts/install.sh` (`curl … | sh`) скачивают self-contained сборку релиза,
  распаковывают её в профиль пользователя и прописывают в PATH — без прав администратора и без
  установки .NET. Повторный запуск той же команды обновляет на месте.
- Терминал проверяет GitHub на новую версию — не чаще раза в сутки и в стороне от старта — и
  показывает строку в главном меню, когда она вышла. `YM_PLAYER_NO_UPDATE_CHECK=1` это отключает.
- `YandexMusicClientOptions.HandlerFactory` — необязательный `DelegatingHandler` перед собственным
  обработчиком клиента: теперь можно логировать и трассировать клиент, созданный напрямую. Тем, кто
  использует `AddYandexMusic`, для этого и раньше был доступен `configureHttpClient`.
- `IYnisonClient.FrameReceived` / `FrameSent` — сырой текст каждого кадра Ynison до разбора.
  Диагностика: когда разобранное состояние выглядит неправильно, это единственный способ увидеть,
  что на самом деле пришло.
- Пример плеера: поиск по артистам — четвёртая вкладка рядом с треками, альбомами и плейлистами, с
  переходом в популярные треки артиста, откуда можно начать воспроизведение.
- Пример плеера: журнал запросов, включается из главного меню клавишей `g`, по умолчанию выключен.
  Пишет HTTP-трафик (строку запроса, заголовки, тела, статус и время) и сырые кадры Ynison в
  `%APPDATA%\yandexmusic-player\requests.log`. Каждая строка перед записью очищается от OAuth- и
  bearer-токенов, кук и паролей — журнал заводят, чтобы кому-то его отдать. Интерактивные сценарии
  входа используют внутри библиотеки собственные HTTP-клиенты и намеренно не записываются.

### Изменено
- Проект примера теперь **`YandexMusicTerminal`** (был `YandexMusic.Player`), его бинарник и архивы
  релиза называются `ymt`, а каталог данных переехал с `yandexmusic-player` на `ymt`. Существующий
  каталог переносится при первом запуске, поэтому сохранённые сессии переживают переименование.
- **Ломающее**: `IYandexMusicClient.CreateYnisonClient` возвращает новый интерфейс `IYnisonClient`
  вместо запечатанного класса `YnisonClient` — теперь его можно подменять и тестировать, как и все
  остальные группы эндпоинтов. `YnisonClient` реализует его без изменений.
- **Ломающее**: `TrackSupplement.Id` и `Lyrics.Id` стали `string?` вместо `long`. API отдаёт этот id
  строкой в одном ответе и числом в другом, а у пользовательских загрузок id вообще не число — такие
  ответы падали при разборе. Ничего от этого значения не вычисляется.

### Исправлено
- Пример плеера: пульт падал при открытии с ошибкой «Encountered malformed markup tag at position 14».
  Значок горячей клавиши устройства закрывал стиль тегом `[/grey]`, который парсер разметки Spectre не
  принимает (закрывает только `[/]`), — исправление из 0.3.0 экранировало скобки, но добавило это.
- Пример плеера: сообщение, оставленное экраном при выходе (ошибка экрана, недоступный Ynison, пустая
  библиотека, «у этого трека нет текста»), висело до конца сессии. Это была обычная запись в консоль,
  а каждый следующий экран — live-представление, отрисованное ниже, поэтому её ничто не убирало.
  Теперь такие сообщения идут через доску уведомлений: главное меню показывает их и гасит через четыре
  секунды, а отказ по тексту песни показывается тостом в экране проигрывания, куда и идёт возврат.
- Пример плеера: вкладки поиска показывали «Ничего не найдено» для запроса, по которому есть
  результаты, — вкладка загружала первую страницу только по нажатию `Enter`. Теперь каждая вкладка
  грузится сразу при показе, рядом с циклом отрисовки, поэтому строка «загружаем» действительно видна,
  а список остаётся живым; при сбое показывается причина и повтор по `Enter`, а не долбёжка API.
- Пример плеера: переход в альбом или плейлист из поиска падал — экраны деталей открывают собственный
  интерактивный дисплей, а Spectre разрешает только один одновременно. Теперь вкладочное представление
  сначала закрывается и открывается заново, сохраняя состояние всех вкладок.
- Пример плеера: сорвавшийся автопереход (не удалось получить пачку радио, не разрешился поток)
  останавливал воспроизведение молча, необработанным исключением задачи. Теперь об этом сообщает новое
  событие `PlaybackController.Failed`, и его показывают плеер и меню.
- Пример плеера: очередь воспроизведения была `List<T>`, который меняли и UI-поток, и колбэк
  «трек закончился» из аудиобэкенда. Теперь изменения очереди сериализованы, а сама очередь —
  неизменяемый снимок, подменяемый по ссылке, так что скип наперегонки с концом трека её не портит.
- Пример плеера: закончившаяся очередь, остановленная затем вручную, дважды сообщала об уходе с одного
  и того же трека, отправляя дублирующий скип в фидбек рекомендаций.
- Пример плеера: отчёты о прослушивании считали паузу прослушиванием, а быстрый скип мог проставить
  событию play-audio идентификатор воспроизведения следующего трека.
- Пример плеера: прощальная строка была захардкожена по-английски вместо локализованного ресурса, а
  экран текста песни ни разу не рисовал строку подсказок, ресурс для которой у него был.
- Ynison: фатальный сбой рукопожатия (отвергнутый токен, некорректный ответ редиректора) заставлял
  `WaitForStateAsync` высиживать весь таймаут и сообщать о таймауте, пряча настоящую причину. Теперь
  ожидание первого кадра падает с той ошибкой, которая действительно случилась.
- Ynison: команда, отправленная в момент обрыва сокета, вылетала из `SendAsync` сырым
  `WebSocketException` или `ObjectDisposedException`; оба теперь обёрнуты в
  `YandexMusicYnisonException`, который вызывающий код уже обрабатывает.
- Ynison: соединения всегда обрывались и никогда не закрывались — `IYnisonSocket.CloseAsync`
  существовал, но не вызывался. При остановке теперь выполняется ограниченное по времени закрытие.
- Ynison: задержка переподключения не сбрасывалась после здорового соединения, поэтому обрыв через
  несколько часов ждал потолок в 64 секунды вместо быстрой попытки.

- Workflow релиза: GitHub Release создаётся черновиком и становится видимым только после того, как
  приложены оба архива плеера, — «последний релиз» больше не может оказаться состоянием, из которого
  скриптам установки нечего скачать. Упавший прогон можно перезапускать: уже опубликованные пакеты
  пропускаются, а существующий черновик дополняется вместо падения на пересоздании.
- CI: скрипты установки проверяются линтерами (ShellCheck, PSScriptAnalyzer) и защищены от переводов
  строк CRLF, с которыми shell-установщик не запустился бы на Linux.

### Удалено
- Пример плеера: одиннадцать строк ресурсов, оставшихся от экранов до live-представлений, которые не
  читал ни один участок кода.

## [0.3.0] - 2026-08-19

### Добавлено
- Клиент Ynison для реального времени (`YandexMusic.Ynison`): подписка на состояние воспроизведения
  аккаунта на всех устройствах и дистанционное управление (пауза/продолжение, следующий/предыдущий
  трек, громкость отдельного устройства, «играть на устройстве») по тому же websocket-протоколу,
  что используют официальные клиенты. Полные модели protobuf-JSON состояния (оригинальные
  snake_case-имена полей протокола), переподключение с ограниченным экспоненциальным бэкоффом,
  готовые билдеры запросов и `IYandexMusicClient.CreateYnisonClient()`, автоматически
  подставляющий токен сессии. Проверено на живом сервисе.
- Сэмпл-плеер: экран пульта Ynison — живое состояние воспроизведения всех устройств аккаунта,
  команды паузы/треков/громкости и «играть здесь» клавишами `1-9`.
- Сэмпл-плеер: действия с треком на экране «сейчас играет» — лайк (`l`), дизлайк с автопропуском
  (`x`), текст песни (`t`) и бесконечное радио похожих треков от текущего трека (`i`).
- Сэмпл-плеер: отчёт о прослушиваниях — каждый старт воспроизведения отправляет play-audio, а
  радио-очереди («Моя волна», похожие треки) шлют фидбек radio-started/track-started/finished/skipped,
  поэтому рекомендации реагируют на фактически прослушанное.
- Сэмпл-плеер: поиск как экран со вкладками — горизонтальная панель вкладок (треки, альбомы,
  плейлисты) над списком результатов в едином live-виде, пагинация «ещё» отдельно на вкладку и
  переход в треклист выбранного альбома или плейлиста; радио-очереди продолжают догружать батчи
  вместо остановки после первого.
- Сэмпл-плеер: статусные сообщения (лайк, ошибки) серые и исчезают через четыре секунды.
- Сэмпл-плеер теперь публикуется self-contained single-file сборками и под **Linux** рядом с Windows
  (zip для win-x64, tar.gz для linux-x64), прикладываются к релизам и артефактам CI.

### Исправлено
- Сэмпл-плеер: пульт больше не падает на разметке Spectre — номерные бейджи устройств («[1]»)
  рендерятся как литеральные скобки.
- Сэмпл-плеер: тексты песен снова работают — supplement-эндпоинт возвращает id строкой, и модель
  теперь принимает и строку, и число.
- Ynison: кадры сервера используют оригинальные snake_case-имена полей протокола (`player_state`,
  `redirect_ticket`); модели теперь корректно их читают (раньше принимался только camelCase, из-за
  чего живые кадры парсились пустыми, а ответ редиректора отвергался).
- `Authentication.PollDeviceTokenAsync` теперь выполняет вход в клиент, когда пользователь подтверждает
  device-code, как и обещала документация. Раньше метод возвращал токен, не применяя его: `IsAuthenticated`
  оставался false, и все последующие вызовы молча уходили без авторизации.
- Сэмпл-плеер: текст песни теперь берётся из supplement-эндпоинта, который отдаёт его напрямую.
  Подписанный `/lyrics` сейчас отвечает 403 «Invalid Sign» даже при точной эталонной подписи,
  что задокументировано у `Tracks.GetLyricsAsync`.
- Сэмпл-плеер: упавший экран (сеть, ошибка API) показывает сообщение об ошибке и возвращает в меню,
  а не закрывает приложение; то же для завершения Ynison-сессии пульта.
- Сэмпл-плеер: запуск без сети (или Ctrl+C во время проверки сессии при старте) больше не удаляет
  сохранённую сессию. Она сбрасывается, только если API сам её отвергает; сетевые ошибки её сохраняют.
- Сэмпл-плеер: файл сессии (`session.json`, токен и cookie) записывается атомарно и доступен только
  владельцу (`0600`) на Linux/macOS вместо мир-читаемого режима по умолчанию.
- Релизный workflow: запрашивает окружение `nuget`, как ожидает полиси Trusted Publishing, и
  прикладывает символьные пакеты `.snupkg` к GitHub Release (в NuGet.org они попадали и раньше,
  но отсутствовали в ассетах релиза).

### Изменено
- `RELEASING.md` теперь существует на каждом языке (`RELEASING.md` + `RELEASING.ru.md`), как README;
  ченджлог следует тому же разнесению (`CHANGELOG.md` + `CHANGELOG.ru.md`). Описание версионирования
  приведено к реальности (MinVer по тегам; запушьте тег — workflow сам создаст релиз).

## [0.2.0] - 2026-07-03

### Добавлено
- `YandexMusicClientOptions.ApiBaseUri` — переопределение базового адреса API для обратного прокси,
  регионального зеркала или локального стаб-сервера в тестах; по умолчанию — официальный хост.
- Оппортунистический HTTP/2 (с прозрачным откатом на HTTP/1.1) на каждом `HttpClient`, который создаёт
  библиотека — включает мультиплексирование соединений.
- Перегрузка `AddYandexMusic(..., configureHttpClient)` и публичная константа `HttpClientName` — теперь
  можно подключить resilience-handler, логирование или свой primary handler к клиенту в пуле
  `IHttpClientFactory`, не полагаясь на внутреннее имя.

### Исправлено
- **Критично**: любой вызов `Pins` (`PinAlbumAsync`, `UnpinAlbumAsync`, `PinArtistAsync`, `UnpinArtistAsync`,
  `PinPlaylistAsync`, `UnpinPlaylistAsync`, `PinWaveAsync`, `UnpinWaveAsync`) падал в рантайме и на Windows,
  и на Linux. Эти методы строили запрос с относительным путём и отправляли его через низкоуровневый метод
  транспорта, который не резолвит относительные пути против хоста API (у `HttpClient` никогда не был
  выставлен `BaseAddress`). Теперь они идут через тот же конвейер запросов, что и все остальные эндпоинты.
- Определение абсолютного URI в конвейере запросов теперь требует схему `http`/`https`. На Linux `Uri`
  разбирал путь вида `/users/1/playlists/2` как абсолютный `file://`-URI (на Windows та же строка
  считалась относительной), из-за чего такие запросы падали с ошибкой «схема 'file' не поддерживается»
  вне Windows.
- `Account.SetSettingsAsync(IReadOnlyDictionary<string, string>, ...)` освобождал тело запроса до
  завершения его отправки, что могло изредка приводить к ошибке или обрезанному телу при реальной
  сетевой задержке.

### Изменено
- `YandexMusic.DependencyInjection`: настройки HTTP-клиента (таймаут, заголовки, прокси, базовый адрес)
  теперь везде последовательно резолвятся из контейнера DI, а не частично из локально захваченной копии —
  исправлен «раздвоенный» баг, при котором заранее зарегистрированный `YandexMusicClientOptions` незаметно
  терял свои настройки прокси/таймаута/заголовков.
- CI теперь собирает и тестирует и на `ubuntu-latest`, и на `windows-latest` (раньше — только на Linux),
  так что подобные ОС-специфичные регрессии ловятся автоматически.
- Планка нулевых предупреждений (`TreatWarningsAsErrors`) теперь распространяется и на тестовый проект;
  NU1900 (недоступный аудит-фид) понижен, чтобы офлайн-сборка не валила CI.

## [0.1.0] - 2026-06-30

Первый публичный релиз оригинальной clean-room реализации.

### Добавлено
- Поддержка `net8.0`, `net9.0` и `net10.0` (мультитаргетинг).
- Высокоуровневый `YandexMusicClient` (`IYandexMusicClient`) с типизированными группами эндпоинтов:
  - **Tracks** — метаданные (одиночно и пачкой), прямая ссылка, тексты, supplement, full-info, трейлер, похожие, play-audio, after-track.
  - **Search** — полный поиск с полиморфным best и секциями по категориям, плюс подсказки (`suggest`).
  - **Albums** — альбом, альбом-с-треками, пачкой, similar-entities, трейлер.
  - **Artists** — brief-info, пагинируемые треки/альбомы, похожие, ссылки, about, info, клипы, донаты, skeleton, трейлер, дискография.
  - **Playlists** — чтение, создание, удаление, переименование, видимость/описание, правка треков, рекомендации, similar-entities, трейлер и др.
  - **Account** — статус, настройки (get/set), permission-alerts, A/B-эксперименты, промокоды.
  - **Library** — лайкнутые и дизлайкнутые треки/альбомы/исполнители/плейлисты/клипы, включая add/remove.
  - **Genres**, **Labels**, **Clips**, **Credits**, **Disclaimers** — метаданные каталога.
  - **Landing** — фид, блоки лендинга, чарты, новые релизы/плейлисты, подкасты, теги.
  - **Radio** (rotor) — dashboard станций, список, info, треки, настройки, фидбэк.
  - **Concerts**, **Metatags** — события и подборки (мета-теги).
  - **Queue**, **Pins**, **Presaves**, **MusicHistory** — личное состояние между устройствами.
- Несколько способов входа: OAuth-токен, официальный OAuth **device-code** flow и best-effort cookie, QR или логин/пароль — всё поверх сериализуемого `AuthSnapshot` (export/import для сохранения и восстановления сессии).
- Пакет `YandexMusic.DependencyInjection`: `AddYandexMusic()` регистрирует scoped-клиент поверх handler'а в пуле `IHttpClientFactory`.
- Типизированная иерархия исключений (`YandexMusicException` и наследники).
- Полная XML-документация публичного API; модульные и интеграционные (по токену) тесты (xUnit).
- Source Link, символьные пакеты (`snupkg`), README в пакетах, документация DocFX, CI/CD на GitHub Actions.

### Производительность
- Source-generation `System.Text.Json` целиком (единый общий «замороженный» `JsonSerializerOptions`); ответы
  десериализуются прямо из UTF-8 потока через `JsonTypeInfo<T>` — экономно к аллокациям, чисто к trim/AOT (`IsAotCompatible`).
- Терпимая обработка перечислений (kebab/UPPER_SNAKE, значение по умолчанию на неизвестном) — новые значения на стороне сервера не ломают ответ.

### Примечание
- Это оригинальная clean-room реализация, написанная по публичному HTTP-API. Она не является производной от
  какого-либо стороннего клиента Яндекс Музыки.
